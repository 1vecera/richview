# RichView core

This crate owns Rich Markdown parsing, rendering, safe style cascades, source diagnostics, report checks and agent knowledge. It performs no filesystem, network or process I/O and is shared by the native app, browser WebAssembly and editor bridge. `render` calls the chart engine once per chart; `check` uses the same output instead of independently laying it out again. Native callers can parse once, resolve references from that AST, then consume it with `render_document(Document, &RenderOptions)` without a second parse. That entry point accepts a trusted AST whose schema and resource limits were established by `parse`.

```rust
let options = richview_core::RenderOptions::default();
let report = richview_core::render("# A local draft", &options).unwrap();
assert!(report.html.contains("A local draft"));
```

`parse` preserves unknown metadata/fences and keeps invalid rich-block source visible with diagnostics. `validate` checks drafts. `validate_publish` enforces the existing title/version publication contract and warns about missing descriptions. `check` returns source findings and chart geometry provenance; its measurement descriptor distinguishes engine layout boxes from browser glyph bounds. It never equates schema validation with readability. `render_compat` supplies the JavaScript package API's `chartWidth`, `reportCard`, style-ref vocabulary and `{html,parsed,hasCharts,diagnostics:{status,charts,parse}}` result using the already-parsed, resolved AST; native hot paths omit that AST serialization. Source/resolved datasets are limited to 16 MiB. `MAX_REPORT_BYTES` caps accumulated rich-block and complete report HTML at 64 MiB, including embedded media/runtime/fonts; amplification returns an actionable `render.output-limit` error rather than a partial report. Resolved media references are checked before duplicating their payloads, including Markdown images inside callouts and prologs.

Generated host adapters use `parse_schema` for familiar schema `.parse`/`.safeParse` operations, including existing required fields and table/image/embed defaults. `resolve_styles_compat`, `custom_properties_to_css` and `builtin_style_source` expose the previous style vocabulary using the same safe Rust implementation. General third-party Zod combinators are not part of the native schema adapter.

Callers supply ordered builtin names or resolved style YAML in `RenderOptions.styles`, and CSV/JSON content or media data URIs in `RenderOptions.data`, keyed by exact references or named IDs. The core does not resolve paths, interpolate secrets or fetch URLs. External assets are diagnosed and `_richview.offline` is false when an export still requires them. Generated wasm-bindgen glue and base64 Wasm can be embedded by a trusted caller to make the interactive runtime available offline; those fields never come from report frontmatter. `runtime_wasm_codec` defaults to `raw`; `gzip` packaging reduces export size and uses the browser's stream decompressor before Rust initialization. A trusted `runtime_url` selects cached host bindings for fast live previews; supply the exact matching JavaScript in `runtime_js` so the renderer can pin it with an integrity hash. Without those bytes, the linked script is omitted and a diagnostic is returned. Final exports use the embedded path.

Canonical `sleek`, `scientific` and `brutalist` YAML and exact offline font CSS are stored in this crate's `assets/`. `editorial` resolves to `brutalist` for source compatibility. Rust embeds the declarative CSS, WOFF2 data and original font notices. Styling is shallow last-wins by section key, with atomic arrays, safe color/font/dimension grammars, actual layout-width/component/motion effects and a reduced-motion floor. Chart overrides are handed to the Rust chart supplier.

Rich blocks cover charts, tables, big/metric values, callouts, images, sandboxed embeds, audio and video. Tables honor source sorting, formatting, row limits and totals; native `details` exposes remaining rows. Browser header clicks delegate to the same public `render_table` implementation, using the embedded resolved-source payload. CommonMark output is sanitized and preserves GFM tables/strikethrough/tasks, footnotes, definition lists, source-safe wikilinks, pull-quote attribution and native MathML from LaTeX. Footnotes remain linked and visible on narrow screens;

To add a rich block, extend its schema in `parser.rs` and dispatch in `blocks.rs`; source parsing and HTML escaping stay shared. To add a style, add declarative YAML/font assets and register its builtin name in `style.rs`. To add a chart type, use the chart crate's source contract; do not build a second chart engine in the report layer.

Run `cargo test -p richview-core`. Contract tests include all supported chart types, every chart of the sourced flagship, metadata/draft compatibility, source lines and unknown fences, CSV/JSON references, real Markdown extensions, native table behavior, asset provenance and HTML/CSS/URL/script safety.
